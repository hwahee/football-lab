# 미식축구 게임 (Football Lab)

앱을 열면 바로 보이는 화면입니다. 7인제 미식축구를 **감독의 입장**에서 플레이합니다 — 작전을 고르고
배치를 다듬은 뒤 START를 누르면, 그 뒤는 선수들과 주사위가 결정합니다.

코드는 `apps/mobile/src/game`에 있고, 기존 보일러플레이트 화면(할 일, 설정, 디자인 시스템 갤러리)은
스코어보드의 톱니바퀴 버튼 뒤(`Main` 스택)로 옮겼습니다.

## 한 플레이의 흐름

```
menu → offense → (handover → defense) → presnap → live → result → … → final
```

| 단계       | 누가 조작하나                                | 화면                                                         |
| ---------- | -------------------------------------------- | ------------------------------------------------------------ |
| `offense`  | 공격 팀                                      | 전략(플레이·방향·패스 성향) / 배치 탭, 내 루트가 필드에 표시 |
| `handover` | (2인 대전만) 기기를 넘기는 중                | 작전은 가려지고 대형만 보임                                  |
| `defense`  | 수비 팀                                      | 전략(수비·커버 간격) / 배치 탭, 내 존·맨 마크가 필드에 표시  |
| `presnap`  | **없음**                                     | 수비가 위장 대형에서 실제 대형으로 이동                      |
| `live`     | **없음** — START 이후에는 버튼이 하나도 없음 | 플레이 진행 + 실시간 중계                                    |
| `result`   | 아무나                                       | 결과, 판정 로그(확률 포함), 다음 플레이                      |

- **AI 대전**: 사람은 항상 블루(홈). 공격일 때는 AI 수비가 스냅 직전에 자리를 잡고, 수비일 때는 AI의 공격
  대형만 보입니다(플레이는 숨김). 난이도는 AI 팀의 능력치와 작전 선택의 날카로움을 바꿉니다.
- **2인 대전**: 기기 하나를 번갈아 넘깁니다. 공격이 "작전 확정"을 누르면 루트가 가려지고, 수비가 작전을
  정한 뒤 START를 누릅니다.
- 블루는 화면 위쪽으로, 레드는 아래쪽으로 공격합니다. "왼쪽/오른쪽"과 `WR·좌` 같은 라벨은 항상 **화면
  기준**입니다.

## 구조

| 경로                         | 역할                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| `engine/`                    | 순수 TypeScript. React·React Native·three 의존 없음 — `bun test`로 검증             |
| `engine/playbook.ts`         | 포메이션, 루트, 수비 임무, 배치 제한(스크리미지 라인을 넘을 수 없음, 센터는 고정)   |
| `engine/sim.ts`              | 한 플레이의 시뮬레이션. 14명의 에이전트 + 모든 경합은 확률 판정                     |
| `engine/game.ts`             | 점수·다운·시계·공격권 (`applyOutcome`은 순수 함수)                                  |
| `engine/ai.ts`               | AI 감독: 상황별 가중치로 작전을 뽑음                                                |
| `render/scene.ts`            | three.js 탑뷰 필드. React 없음 — 브라우저 캔버스에서도 그대로 동작                  |
| `FieldView.tsx`              | expo-gl 컨텍스트에 three.js를 붙이고 렌더 루프를 돌림                               |
| `view.ts`                    | 엔진 좌표(공격 기준) ↔ 월드 좌표 변환, 화면에 그릴 프레임 구성                      |
| `useGameSession.ts`          | 단계 전환과 플레이 루프. 진행 중인 시뮬레이션은 ref에 두고 React 상태는 UI용만 유지 |
| `GameScreen.tsx`, `ui/kit.*` | 화면과 게임 전용 디자인 시스템([game-design-system.md](game-design-system.md))      |

### 확률로 진행된다는 것

플레이가 시작되면 결과는 **두 작전과 난수 스트림**으로만 정해집니다. 선수는 단순한 에이전트(루트 주행,
블록, 러시, 커버, 추격)이고, 서로 맞붙는 순간마다 능력치와 위치로 계산한 확률에 주사위를 굴립니다.

| 경합               | 판정                                      | 확률에 영향을 주는 것                   |
| ------------------ | ----------------------------------------- | --------------------------------------- |
| 블로커 vs 러셔     | `shed` (블록 이탈)                        | 파워 차이, 런/패스 블록, 볼캐리어 근접  |
| 리시버 vs 코너     | `jam`, `burn` (컷에서 따돌림)             | 커버 간격(밀착일수록 위험), 스킬 차이   |
| 페이크 vs 수비     | `bite` (플레이 액션에 속음)               | 수비 임무(런 스톱이 가장 잘 속음), 스킬 |
| 패스 vs 커버       | `catch` / `incomplete` / `interception`   | 수비와의 거리, 패스 거리, 압박, 스킬    |
| 러셔 vs 쿼터백     | `sack` / `escape`                         | 스킬 차이                               |
| 볼캐리어 vs 태클러 | `tackle` / `brokenTackle` (+ 드물게 펌블) | 스킬·파워 차이, 주변 수비 수            |
| 킥                 | 필드골 성공 여부, 펀트 거리               | 거리 (필드골 성공률은 작전 카드에 표시) |

판정마다 확률이 `sim.events`에 기록되어 결과 화면의 로그에 그대로 나옵니다. 난수는 시드 기반
(`engine/rng.ts`)이라 같은 시드와 같은 작전은 같은 플레이를 재현합니다 — 테스트가 이 성질에 기댑니다.

밸런스의 큰 틀(가위바위보): 런은 블리츠·런 스톱에 막히고, 퀵 슬랜트·스크린은 블리츠를 벌하고, 딥 샷은
밀착 커버를 벌하고, 프리벤트는 장거리를 막는 대신 짧은 전진을 내줍니다.

### 단순화한 규칙

- 킥오프 없음: 득점 뒤와 후반 시작은 자기 진영 25야드에서 시작
- 터치다운 뒤 보너스 킥은 자동(94% 판정)
- 인터셉션은 잡은 자리에서 끝(리턴 없음), 엔드존 안이면 터치백
- 동점이면 무승부, 반칙 없음

## 개발 메모

- **expo-gl은 네이티브 모듈**입니다. 이 변경을 받은 뒤에는 개발 빌드를 다시 만들어야 합니다
  (`bun run --cwd apps/mobile android` / `ios`). Expo Go나 예전 개발 빌드에서는 필드가 뜨지 않습니다.
- 필드에는 텍스처와 텍스트를 쓰지 않습니다(expo-gl에는 글자를 그릴 캔버스가 없음). 야드 숫자는
  7세그먼트 사각형으로 만듭니다.
- 좌표계: 엔진은 항상 "공격 팀 기준"(y=0 자기 골라인, y=100 상대 골라인)으로 계산하고, 어느 팀이 화면
  어느 쪽으로 공격하는지는 `view.ts`만 압니다.
- 자동화: `apps/mobile/e2e/game-play-a-snap.yaml` (Maestro).
